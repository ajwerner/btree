# ajwerner/btree: review and roadmap (2026-09-29)

Scope: make this library the ordered map / order-statistic tree for the
assigner's `Supply.fit` index (see the fit-index brief, R1–R11), with
google/btree-class copy-on-write behaviour, pluggable free lists, and
performance at or above google/btree, on Go ≥ 1.26.

Verdict: the core (refcounted CoW nodes, `mut`, augmentation hook,
low-level iterator) is the right design and benchmarks at parity with
google/btree on point operations. It is not shippable today: four bugs, a
compile-time degree of 64 that costs 25% on the clone-heavy workload, no
way to define an augmentation outside the module, and no test harness that
would have caught any of it. Everything below is ordered by what unblocks
adoption first.

## 1. Bugs (all reproduced at HEAD `1cedbd5`)

Repros live in `../scratch/btree-harness/{bugs,rank}_test.go` (a module that
`replace`s this repo; run with `go test -run Test ./...`).

1. **Clone drops values.** `Node.clone` copied `count`, `aug`, `keys`,
   `children` but not `values`. After `Clone()`, the first CoW copy of any
   node zeroes every value in it, in `Map` and `orderstat.Map`. Only `Set`
   (`V = struct{}`) was ever tested, so it never showed. **Fixed in the
   working tree** (`c.values = n.values`, `internal/abstract/node.go:134`).
   The "fix bug in clone" commit `ea7f2ad` fixed the adjacent `aug` copy
   direction and missed this one.
2. **`orderstat.Iterator.Rank()` is wrong at height ≥ 3.** It adds the
   sibling subtrees of the current node and of exactly one ancestor
   (`order_stat.go:143-152` ascends once). At 300k ints (height 3):
   `Rank(5000)=904`, `Rank(16384)=0`, `Rank(100000)=1696`,
   `Rank(299999)=5087`. `SeekNth` is correct. Fix: walk every frame of the
   iterator stack, or (better) carry a prefix aggregate in each frame so
   `Rank()` is O(1) at the cursor (see §4).
3. **Iterator panics on over-run.** `Next()` on an exhausted iterator whose
   root is interior descends into `children[count+1]` → nil dereference.
   `Prev()` on a freshly reset iterator (or past the beginning) descends
   into `children[-1]` → index out of range. Both `iterator.go:128-135` and
   `:156`. `Next`/`Prev` must be no-ops (stay invalid) when `!Valid()`.
4. **`go test ./...` does not build** on Go ≥ 1.24: vet rejects
   `ExampleBlog` (`orderstat/order_stat_test.go:91`). Rename to
   `Example_blog` or `ExampleSet_SeekNth`.

Latent, not yet bitten:

5. **`Map` is a value type.** `m2 := m` aliases the root without `incRef`.
   If `m2` then splits the root, `m.root` points at a node that is now a
   child with ref 1; `m.Reset()` frees `m2`'s subtree. google/btree avoids
   this by handing out `*BTreeG`. Return `*Map` from a `New` constructor
   (keep `Clone()` returning `*Map`).
6. **Merge path clones a shared sibling just to free it**
   (`node.go:517`): `mut(&n.children[i+1])` copies a whole node so that
   `decRef(false)` can release it. Cheaper: `incRef` the grandchildren and
   `decRef(recursive=true)` the shared sibling.
7. **Concurrency contract is under-specified.** "Read operations are safe"
   is true for readers on a snapshot (a `Clone`), not for readers of the
   same `Map` value concurrent with a writer (`Get` reads `t.root`
   unsynchronised). State it the way the brief needs it: single writer per
   map, any number of readers per snapshot, `Clone` safe against readers.

Reading of the numbers:

- Point ops: parity or a 5–15% lead. The fixed-array node layout and the
  inline iterator stack are doing their job.
- Clone-heavy: at degree 64 the tree is 25% slower than at degree 16 on the
  round benchmark and 1.7× slower than google on clone-each-time. The brief's
  degree-16 measurement holds here too, and at degree 16 this library is
  within noise of google/btree at degree 16 with one third the allocations.
- CPU profile of the 20k round (degree 64): `cmpFit` 28% + `find` 15%
  (comparison via indirect call), `madvise` 10% (`sync.Pool` churn),
  `decRef` 8.5%, `duffcopy`/`memmove`/`duffzero` 12% combined. The last
  bucket is the fixed-array cost: `clone` copies all 127 slots
  (`c.keys = n.keys`) and `putLeafNode` zeroes all of them (`*n = Node{}`)
  regardless of `count`.
- The augmentation costs ~5% on mutation (orderstat vs plain) and nothing
  on reads. Acceptable.

## 4. Proposed design

### 4.1 Node layout and degree (R6)

Go cannot parameterise an array length by a type parameter, so the choice
is between one compile-time degree and slice-backed nodes with a runtime
degree. Recommendation: **runtime degree, slice-backed, google-style**, with
one twist:

```go
type entry[K, V any] struct { k K; v V }     // for V = struct{}, entry == K
type node[K, V, A any] struct {
    ref      int32
    count    int16
    aug      A
    entries  []entry[K, V]  // cap = 2*degree-1
    children []*node[K, V, A] // nil for leaves, cap = 2*degree
}
```

- One backing slice for keys and values instead of two arrays. Sets pay no
  value overhead (fixes minor item 8 in the brief).
- `clone` copies `count` entries, not the whole array, and free zeroes only
  `[:count]`, removing the `duffcopy`/`duffzero` share of the profile.
- Steady state with a free list is 0 allocs/op (as measured for google).
- A cold node is 3 allocations (node, entries, children). google's
  benchmark shows this indirection costs ≤ 5% on `Get`; the degree-16 round
  benchmark shows the copy-volume win is worth more than that.

Default degree 16 (matching cockroach and the assigner's measurement);
constructor takes it. Keep `int16` counts.

### 4.2 Ownership, release, free lists (R1)

Keep atomic refcounts rather than google's "context pointer" scheme: refcounts
let the last owner of a shared node recycle it, where google leaks every
node that was ever shared to the GC. Add:

```go
type FreeList[K, V, A any] interface {
    Get(leaf bool) *node[K, V, A] // node is exported-opaque
    Put(*node[K, V, A]) bool
}
func NewFreeList[K, V, A any](size int) *BoundedFreeList[K, V, A] // mutex + slice, like google
func NewSyncPoolFreeList[K, V, A any]() ...                          // today's behaviour, opt-in
func New[K, V any](cmp func(K, K) int, opts ...Option) *Map[K, V]     // WithDegree, WithFreeList
func (m *Map[K, V]) Clear(recycle bool)                              // Reset today; keep alias
```

`Clear(true)` walks only nodes whose ref drops to zero, so releasing a
private clone is O(touched path), not O(n).

### 4.3 Augmentation layer (R2, R3, R4, R5)

Export today's `internal/abstract` as `btree/aug` (or fold it into the root
package; the root `Map` is already a trivial wrapper). Keep the low-level
`Updater.Update(node, UpdateInfo{Action, ModifiedOther, RelevantKey})`
hook because the interval bound (a max, not invertible) needs it. Layer a
monoid adapter on top for the common case:

```go
// Go 1.26 self-referential constraint.
type Monoid[A Monoid[A]] interface {
    Combine(A) A
}
type Contribution[K, V, A Monoid[A]] interface {
    Of(k K, v V) A
    Uncombine(a, b A) (A, bool) // optional: group inverse for O(1) removal
}
type Pair[A Monoid[A], B Monoid[B]] struct{ A A; B B } // composition
```

`count`, `sum(x)`, `count(x==0)` are each a five-line `Contribution`; the
assigner's aug is `Pair[Count, Pair[Sum, Empties]]`. The adapter implements
`Updater` generically: incremental on Insertion/Removal/Split when
invertible, full O(degree) recompute otherwise.

Primitives on the iterator, each one descent:

- `Prefix() A` — aggregate of everything strictly left of the cursor. Store
  the running prefix in each iterator frame during descent (`SeekGE`,
  `SeekNth`, `First`) so `Prefix()`/`Rank()` is O(1) after a seek and stays
  correct across `Next`/`Prev` (fixes bug 2 by construction, removes the
  second descent the brief flags in R5).
- `SeekWhere(pred func(prefix, next A) bool)` — descend maintaining the
  prefix, stop at the first position where `pred` flips. `SeekNth(k)` is
  `pred = prefix.n + next.n > k`; "first host in pool P with x ≤ b" is the
  same call with a different predicate.
- `Map.Rank(key) (int, found)` and `Map.Aggregate(lo, hi) A` — the latter
  as `prefix(hi) − prefix(lo)` when invertible, else the standard
  two-boundary O(log n) walk. `Count(lo, hi)` is `Aggregate` on `Count`.

`orderstat` becomes ~30 lines over this; `interval` keeps its hand-rolled
overlap scan on the low-level iterator (it is a different traversal).

### 4.4 Iterator surface (R7)

Keep the stateful, zero-allocation iterator as the primary API. Add
`iter.Seq2[K, V]` views (`All`, `Range(lo, hi)`, `Descend`) for
convenience; document that they cost a closure call per element. `Next`/`Prev`
on an invalid iterator stay invalid.

### 4.5 Mutating cursor (R11, later)

The iterator already holds the frame stack. A `Cursor` variant `mut`s each
frame on first write (pinning a uniquely-owned root-to-leaf path), then
supports `SetValue` (no descent), `Delete` (leaf removal; rebalance only when
the leaf underflows, then re-seek from the parent frame), `Rekey` (if the new
key sorts between the leaf's neighbours, swap in place and fix the prefix;
otherwise `Delete` + hinted `Insert` from the lowest common frame), and
`Insert` (hinted from the current frame). One live cursor per map;
augmentations are re-applied up the pinned path after each op. Build after
§4.1–4.3, with the R9 `seek→Rekey` vs `seek→Delete+Upsert` benchmark as the
acceptance test.

## 5. Go ≥ 1.26 hygiene

Toolchain reality on this machine: go1.24.0 installed, go1.27.1 is current
stable and downloads via `GOTOOLCHAIN=go1.27.1`. `go fix -diff ./...` under
1.27.1 only wants `interface{}` → `any` and `for i := range N`.

- `go.mod`: `go 1.26.0`, no `toolchain` line; CI matrix `1.26.x`, `1.27.x`.
  Generic methods are 1.27-only; do not depend on them while 1.26 is the
  floor.
- Drop `testify` (the only dependency). A data-structure library should be
  dependency-free; the existing uses are `require.Equal`.
- Apply `go fix ./...`; `go vet ./...` clean, including 1.27's `stdversion`
  check that `go test` now runs by default.
- Benchmarks use `testing.B.Loop` (1.24+, and 1.26 no longer blocks inlining
  in the loop body). Tests use `math/rand/v2` with fixed seeds; report the
  seed on failure.
- Fuzz target (`testing.F`) driving the differential model with a byte-string
  op script; run the differential and invariant tests under `-race` in CI.
- Green Tea GC is on by default in 1.26 and favours many small objects; the
  slice-backed node layout is fine under it. 1.27's size-specialised malloc
  makes the cold 3-alloc node cheaper still.
- GitHub Actions: `gofmt -l`, `go vet`, `staticcheck`, `govulncheck`,
  `go test -race -count=3 ./...`, benchmarks with `benchstat` against the
  previous tag on demand.
- Package docs with the ownership/concurrency contract from §1.7, one
  runnable example per package, `README` status badge to "stable" only at
  `v1.0.0`. Tag `v0.2.0` after phase 1, `v1.0.0` after phase 2.

## 8. Phase 2 results (same day)

Landed on `harden`: `aug.Monoid` / `aug.Group` / optional `aug.Equaler` and
`aug.Folder`, `aug.MonoidUpdater`, ready-made `Count`, `Sum`, `PairOf`;
`UpdateInfo` now carries the entry value and a `Replacement` action (value
derived aggregates were silently stale on upsert of an existing key before);
`Map.Total`, `Map.Prefix(key)`, `Map.Aggregate(lo, hi)`,
`Iterator.Prefix()`, `Iterator.SeekWhere(pred)`. orderstat is 40 lines over
`Count` and gains `Rank(key)`, `Nth`, `Count(lo, hi)`; its iterator `Rank()`
returns the insertion rank past the end instead of -1.

Prefixes are computed lazily (walking the iterator's frames) so seeks and
iteration pay nothing; `Rank()` at the cursor is O(degree * height). The
eager per-frame prefix is deferred to the mutating cursor (phase 3), where
its O(1) `Rank()` after `Next` has a consumer.

orderstat, ints, degree 16 (ns/op):

| op | 10k | 1M |
|----|----:|---:|
| SeekGE (reference) | 68 | 229 |
| Map.Rank(key) | 83 | 239 |
| SeekGE + Iterator.Rank() | 97 | 289 |
| SeekNth | 146 | 306 |
| Count(lo, lo+n/10) | 145 | 439 |

`Folder` (one call per node span instead of one per child) is what brings
`Rank(key)` to within 10 ns of a plain seek; `SeekNth` still pays an
interface call per child visited and is the next thing to fold.

## 9. Phase 3 results (same day)

Landed on `harden`: `aug.Cursor` (R11). It embeds `Iterator`; the first
write pins the root-to-leaf path with `mut` (copy-on-write per frame), then
`SetValue`, `Delete`, `Rekey` and a hinted `Upsert` act in place when the
leaf allows it (no underflow for `Delete`, no overflow for `Upsert`, key
still between neighbours for `Rekey`) and maintain augmentations up the
pinned path, stopping when an Updater reports no change. Otherwise they use
the top-down algorithm and re-seek. `Delete` leaves the cursor on the
successor; `Rekey` on the moved entry; `Upsert` on the upserted entry.
`Rekey`'s fallback is `Delete` in place followed by the hinted `Upsert`, so
a nearby move needs no further descent.

Differential test at degrees 2, 3 and 16 mixes every cursor operation with
seeks, clones taken mid-stream (checked for isolation afterwards) and
`Verify`, which recomputes every augmentation. Exposed as `btree.MapCursor`
/ `SetCursor` and `orderstat.Cursor` (with `Rank` and `SeekNth`).

Benchmark (`aug.BenchmarkRekey`): 20k-host fleet, 24-byte key, count
augmentation, snapshot re-cloned every 200 moves, each move bumps
`fullness` by 3:

| seek + Delete + Upsert | Cursor.SeekGE + Rekey |
|---:|---:|
| 424 ns | 266 ns |

Not done: an eager per-frame prefix so `Rank()` is O(1) after `Next`
(lazy `Prefix()` works on cursors today at O(degree * height)).

## 10. Iteration experiments

`Map.All`, `Backward`, `Range(lo, hi)`, `From(lo)` as `iter.Seq2` views
(recursive node walk, no iterator stack), plus `Min`/`Max`. Measured at 1M
int entries, degree 16:

| walk | ns per item |
|------|------------:|
| Iterator, empty body | 2.5 |
| All, empty body | 5.2 |
| callback walk (google/btree style), empty body | 3.4 |
| Iterator, summing keys | 6.2 |
| All, summing keys | 6.0 |

The range-over-func rewrite costs about 1.8 ns per yield over a plain
callback, and about 2.7 ns over the stateful iterator when the body is
empty; once the body touches the keys the memory traffic dominates and the
two are equal. An `All` built on the stateful iterator was slower (7.3 ns),
so the recursive walk stays. `Range(lo, lo+10)` costs 128 ns against 82 ns
for `SeekGE` plus ten `Next` calls, since it re-runs `find` at every level
on both bounds; use the iterator for short scans.

## 11. Phase 4 experiments (same day)

Profile of the round on the slice-backed core (fleet 20k, degree 16): within
the benchmark's own time `find` plus the comparator is 54%, refcount traffic
(`decRef` during `Clear`, child `incRef` in `clone`) about 25%, node copies
8%. Experiments:

- **Non-atomic refcounts** (plain arithmetic, temporary): 2-7% faster on
  the round and on clone-each-time. The refcount cost is the memory traffic
  of touching every child's header when a node is copied or freed, not the
  atomic instructions. Atomics stay; no "unsynchronized" mode.
- **Native `SeekNth`** (descend by child counts through the low-level
  iterator) versus `SeekWhere` with a rank predicate: 94 ns versus 310 ns at
  1M, 27 versus 149 at 10k. `SeekWhere` pays a predicate call and a
  `Combine` per child visited; it stays as the general primitive and
  `SeekNth` is native again. `SeekWhere` users with hot predicates should
  expect this gap.
- **`DefaultFreeListSize` 32 → 256.** A round frees about 230 nodes; with
  256 the default configuration matches a 1024-node list (50.3 µs versus
  50.3 µs at 20k), where 32 spilled to the GC (70 µs).
- **Cursor-based round.** Replacing delete + upsert with `Cursor.SeekGE` +
  `Rekey` in the round benchmark:

| fleet | google/btree deg 16 | this, delete + upsert | this, cursor Rekey |
|------:|------:|------:|------:|
|  1k   | 26.0 µs | 22.6 µs | 19.9 µs |
|  5k   | 38.6 µs | 35.5 µs | 29.4 µs |
| 20k   | 53.4 µs | 50.3 µs | 41.9 µs |

Both this-library columns use the default free list and 2 allocations per
round (the clone's two structs).
